## 二、Bug 修复

### 2.1 🐛 矩阵网格尺寸不联动

**现象**：矩阵计算器中，把 A 矩阵尺寸从 2×2 改成 3×3，下面的输入框仍然是 2×2。

**根因**：`_buildParams()` 使用 `def.rows` / `def.cols`（静态默认值），没有读取滑块的实际值。

**修复**（[scene-base.js:212-217](client/js/scene-base.js#L212-L217)）：

```js
// 通过命名约定匹配：matrix_A → 读 A_rows / A_cols
const suffixMatch = key.match(/^matrix_(.+)$/);
if (suffixMatch) {
    const suffix = suffixMatch[1];
    if (this.params[suffix + '_rows'] !== undefined) rows = this.params[suffix + '_rows'];
    if (this.params[suffix + '_cols'] !== undefined) cols = this.params[suffix + '_cols'];
}
```

**联动触发**（[scene-base.js:278-281](client/js/scene-base.js#L278-L281)）：

```js
// 尺寸滑块 change 时重建整个参数面板
if (key.endsWith('_rows') || key.endsWith('_cols')) {
    this._buildParams();
}
```

### 2.2 🐛 `val.toFixed is not a function`（用户记忆为 "VOT" 报错）

**现象**：首次打开矩阵计算器时弹出「场景加载失败: val.toFixed is not a function」。

**根因**：`_updateParamValueLabel()` 对所有 param 值调 `.toFixed(2)`，但 `choice` 类型参数的值是字符串（如 `"multiply"`），字符串没有 `.toFixed()` 方法。

**修复**（[scene-base.js:321-329](client/js/scene-base.js#L321-L329)）：

```js
_updateParamValueLabel(key, val) {
    if (typeof val === 'number') {
        span.textContent = Number.isInteger(val) ? val : val.toFixed(2);
    } else {
        span.textContent = '';  // 非数字不显示
    }
}
```

同时修了同一类问题的两个连锁 bug：
- **下拉框 change 事件**用 `select.value` 直接赋值，不再调 `parseFloat()`（会 NaN）
- **滑块初始化**用 `this.params[key] ?? def.default`，不再用静态 `def.default`（否则 preset 改动后重建面板值会跳回默认）

## 三、新场景开发

### 3.1 场景 0.0：「矩阵的列——线性变换的密码」

**核心问题**：一个矩阵到底是怎么对应几何变换的？

**答案**：矩阵第 j 列 = 标准基向量 eⱼ 变换后的坐标。竖着读列 = 基向量的「目的地」，横着读行 = 各基向量在某输出维度上的「影子」。

**文件**：
- 后端：[server/scenes/ch0_r0_matrix_columns.py](server/scenes/ch0_r0_matrix_columns.py)（~310 行）
- 渲染器：[client/js/renderers/ch0_r0_matrix_columns.js](client/js/renderers/ch0_r0_matrix_columns.js)（~430 行）

**功能**：
- 支持 2×2（平面）和 3×3（空间）两种模式
- 灰色半透明 ghost 箭头指向原始基向量位置
- 彩色箭头指向变换后位置（= 矩阵列向量）
- 白色线框显示原始正方形/立方体，蓝色线框+半透明面显示变换后形状
- 7 个预设（4 个 2×2 + 3 个 3×3）
- **动画**：1.5s ease-out cubic，基向量从原始位置滑翔到变换后，形状同步变形
- 矩阵面板同时显示起点 I（恒等）和终点 A

---

### 3.2 场景 0.1：「逐列拆解——行与列的几何含义」

**核心问题**：矩阵的某一列或某一行单独在做什么？

**答案**：
- 列 1 只响应输入 x 坐标 → 输出全在 col₁ 方向上
- 列 2 只响应输入 y 坐标 → 输出全在 col₂ 方向上
- 完整变换 = 列 1 贡献 ⊕ 列 2 贡献（向量加法）

**文件**：
- 后端：[server/scenes/ch0_r1_column_decompose.py](server/scenes/ch0_r1_column_decompose.py)（~210 行）
- 渲染器：[client/js/renderers/ch0_r1_column_decompose.js](client/js/renderers/ch0_r1_column_decompose.js)（~310 行）

**功能**：
- 4 种显示模式：compare（并排对比）/ full（仅完整）/ col1_only / col2_only
- 红色 = 仅第 1 列变换（正方形坍缩为沿 col₁ 的线段）
- 青色 = 仅第 2 列变换（正方形坍缩为沿 col₂ 的线段）
- 蓝色 = 完整变换（平行四边形 = 红 ⊕ 青）
- compare 模式下虚线连接对应顶点，直观展示加法关系
- 4 个预设
- **动画**：1.6s ease-out cubic，所有形状同步从单位正方形变形

## 四、动画系统（重点整理）

### 4.1 架构

动画系统由四个组件构成，目前实现在 `ch0_r0` 和 `ch0_r1` 两个渲染器中：

```
┌─ buildScene(data)
│   ├── 创建可更新对象（箭头 + 线框 + 面），初始状态 = 恒等变换（t=0）
│   ├── 保存动画数据到 this._animData = { arrows, shapes, ... }
│   └── setTimeout → _startAnimation()
│
├─ _startAnimation()
│   └── _animFrame() ← requestAnimationFrame 递归
│         └── _interpolateToT(t)  // ease-out cubic: t = 1-(1-t)³
│               ├── arrows: start.lerp(end, t)
│               └── shapes: 逐顶点线性插值
│
└─ _addAnimationButton() → 在 solution 面板顶部插入「▶ 演示动画」按钮
```

### 4.2 三个工厂函数

| 函数 | 产出类型 | 更新方法 | 原理 |
|------|---------|----------|------|
| `createAnimatableArrow(color, label, thickness)` | `THREE.Group` | `.update(endPoint)` | 重设 Group 的 rotation（Y→目标方向）、body.scale.y（长度）、cone/sprite 位置 |
| `createUpdatableWireframe(verts, edges, color)` | `THREE.LineSegments` | `.updateVertices(newVerts)` | 直接改写 BufferGeometry 的 position buffer，设 `needsUpdate = true` |
| `createUpdatableFaces(verts, faces, color)` | `THREE.Group` | `.updateVertices(newVerts)` | dispose 旧三角形、重建新三角形（因为顶点数可变） |

### 4.3 动画数据协议

```js
this._animData = {
    arrows: [
        { arrow, start: [1,0,0], end: [a11, a21, 0] },  // 从 e₁ 到 col₁
        { arrow, start: [0,1,0], end: [a12, a22, 0] },  // 从 e₂ 到 col₂
    ],
    shapes: [
        { wire, face, original: [[...],...], target: [[...],...] },
        // original = 单位正方形（可能带偏移），target = 变换后形状
    ],
};
```

### 4.4 重播按钮与 _computeAndRender 覆写

**必须覆写的原因**：基类的 `_computeAndRender()` 调用 `_updateSolutionInfo()`，后者用 `innerHTML = html` 覆盖 solution 面板，会把动画按钮清除。

**修复**：子类覆写 `_computeAndRender`，在 `super` 返回后重新插入按钮：

```js
async _computeAndRender(params, showLoading) {
    await super._computeAndRender(params, showLoading);
    this._addAnimationButton();  // 重新插入，不会被覆盖
}
```

## 五、标签定位修复

### 5.1 问题

ch0_r0 动画中，箭头标签（如 "e₁ → 第1列"）出现在错误的位置——在 Y 轴负半轴而非向量旁边。

### 5.2 根因

标签 sprite 的初始位置用**世界坐标**设置（如 `dir * (len + offset)`），但箭头 Group 后续通过 `setRotationFromQuaternion` 旋转使 Y 轴对齐向量方向。sprite 作为 Group 的子对象，跟着一起旋转，导致世界空间中出现双重旋转。

### 5.3 修复

在 `createAnimatableArrow` 的 `update(endPoint)` 和 sprite 位置设置中，统一使用**局部 Y 轴坐标**：

```js
// ✅ 正确：在 Group 的局部空间中，Y 轴就是箭头方向
sprite.position.set(0, len + coneHeight + 0.3, 0);

// ❌ 错误（旧代码）：在世界空间中计算，然后被 Group 旋转二次加工
sprite.position.copy(dir.clone().multiplyScalar(len + offset));
```

同样的原理适用于锥头 (`cone.position.y = len`) 和柱身 (`body.position.y = len / 2`)。

## 六、讲解面板 LaTeX 转义问题

### 6.1 问题

ch0_r1 讲解面板中，矩阵公式显示为原始 LaTeX 源码：
```
A = \\begin{pmatrix}0.0 &amp; -1.0 \\\\ 1.0 &amp; 0.0\\end{pmatrix}
```
KaTeX 没有渲染，而是显示了源码。其中 `&amp;` 是 `&` 被 HTML 转义后的结果。

### 6.2 根因

**Python f-string 中反斜杠多了一层转义**。以下是错误写法和正确写法的对比：

| LaTeX 期望 | Python 错误写法 | 实际产出 | Python 正确写法 |
|-----------|----------------|---------|----------------|
| `\begin` | `\\\\begin` | `\\begin`（两个反斜杠） | `\\begin` |
| `\\`（换行） | `\\\\\\\\` | `\\\\`（四个反斜杠） | `\\\\` |
| `\underbrace` | `\\\\underbrace` | `\\underbrace` | `\\underbrace` |
| `\end` | `\\\\end` | `\\end` | `\\end` |
| `\text` | `\\\\text` | `\\text` | `\\text` |

**规则**：Python f-string 中，要产出 n 个反斜杠，需要写 2n 个。LaTeX 命令（`\begin`、`\underbrace` 等）需要 1 个反斜杠 → Python 写 2 个；LaTeX 换行（`\\`）需要 2 个反斜杠 → Python 写 4 个。

### 6.3 修复

[ch0_r1_column_decompose.py:138-141](server/scenes/ch0_r1_column_decompose.py#L138-L141) —— 所有 `\\\\` 降一级为 `\\`，所有 `\\\\\\\\` 降一级为 `\\\\`。

### 6.4 排查方法

```bash
# 直接 curl API 用 Python repr() 看原始内容中的反斜杠数量
curl -s -X POST http://localhost:8765/api/scene/ch0_r1_column_decompose \
  -H "Content-Type: application/json" \
  -d '{"mode":"compare",...}' | python -c "
import json, sys
d = json.load(sys.stdin)
print(repr(d['data']['lecture']['sections'][1]['content'][:300]))
"
```

如果看到 `\\\\begin` 说明多了一层转义；`\\begin` 则是正确的。

## 八、给未来的 AI（或失忆后的自己）

1. **新增动画场景**：从 `ch0_r0` 或 `ch0_r1` 复制三个工厂函数 → 在 `buildScene` 中填充 `_animData` → 覆写 `_computeAndRender` 保留按钮。详见 [docs/DEV_GUIDE.md](docs/DEV_GUIDE.md) 第十章。
