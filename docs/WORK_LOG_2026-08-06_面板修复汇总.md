### 8. 列折叠/展开时 canvas 跳动（本次核心修复）
- **根因**：ResizeObserver 回调在浏览器 layout→paint 夹缝中执行。此时调用 `renderer.setSize()` 触发 WebGL framebuffer resize，打断 CSS transition 的渲染管线，中间过渡帧被跳过
- **尝试过的错误方案**：
  - 4 个 dock zone ResizeObserver + debounce 120ms → 画面闪烁 + 跳动
  - 单个 viewer ResizeObserver + RAF 包装 → 仍然跳动
- **最终方案**：完全废弃 ResizeObserver，把 `resize()` 放入 `animate()` 渲染循环开头，每帧同步 canvas 尺寸
- **为什么正确**：
  - `resize()` 在 RAF 回调中执行，与 CSS transition 的 paint 在同一帧的不同阶段，不会打断
  - `renderer.setSize()` 在尺寸不变时内部短路（零开销）
  - 天然支持任何导致 viewer 尺寸变化的情况，不限于 CSS transition

## 教训

1. **ResizeObserver 不适合与 WebGL canvas resize 配合使用**——它运行在 layout→paint 夹缝，而 WebGL 操作可能干扰 paint 管线
2. **每帧轮询 `getBoundingClientRect()` + `setSize()` 比 ResizeObserver 更可靠**——`setSize()` 内部短路保证了零开销，不存在时序问题
3. **`!important` 是覆盖内联样式的唯一手段**——JS resize 手柄写 `el.style.height`，只有 `!important` 能覆盖
4. **可见性控制的守卫应该放在最底层**——`DockPanel.show()` 而非每个调用点
